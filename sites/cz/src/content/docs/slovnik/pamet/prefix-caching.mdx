**Prefix caching** je znovupoužití už zpracovaného začátku kontextu.
Když každý dotaz začíná stejným systémovým promptem nebo stejným
dokumentem, model nemusí tento prefix počítat znovu. U RAG a agentů
to může výrazně zkrátit [TTFT](/slovnik/vykon/ttft/).

## Rychlá odpověď

- **Cache se týká prefixu**, ne celého dotazu.
- **Nejvíc pomůže**, když se opakuje dlouhý systémový prompt nebo
  dokument.
- **Není to zdarma** — cache bere paměť a musí se invalidovat.
- **Sdílená cache mezi uživateli** může být bezpečnostní riziko.

## Jak to funguje

1. První dotaz zpracuje prefix a uloží KV cache.
2. Další dotaz se stejným prefixem cache znovu použije.
3. Počítá se jen nová část (dotaz a odpověď).
4. Když se prefix změní, cache se invaliduje.

## Kde to pomůže

- **Systémový prompt** — dlouhý návod pro všechny dotazy.
- **RAG** — stejný dokument nebo instrukce.
- **Agenti** — stejná historie a nástroje.
- **Chat** — multi-turn konverzace.
- **Dávkové zpracování** — stejný kontext pro mnoho úloh.

## Kde to nepomůže

- Každý dotaz má jiný prefix.
- Kontext je krátký.
- Cache je malá a rychle se evictuje.
- Model nebo engine cache nepodporuje.

## Rizika

- **Paměť** — cache zabírá KV cache.
- **Soukromí** — sdílená cache mezi uživateli.
- **Neplatná data** — změna dokumentu bez invalidace.
- **Komplexita** — těžší monitoring a ladění.

## Co měřit

- **TTFT** před a po.
- **Hit rate** cache.
- **Paměť** cache.
- **Kvalita** odpovědí.
- **Bezpečnost** — kdo cache sdílí.
