**Function calling** (také **tool calling**) je schopnost modelu
vrátit strukturovaný požadavek na zavolání funkce. Model sám funkci
nevykoná — jen řekne „zavolej tuhle funkci s těmito argumenty“.
Aplikace volání provede, výsledek vrátí modelu a ten pokračuje.

## Rychlá odpověď

- **Model navrhne volání**, aplikace ho provede. Bez aplikace se nic
  nestane.
- **Argumenty jsou strukturované** (JSON), ne volný text. To umožňuje
  validaci a audit.
- **Není to totéž co MCP.** Function calling je schopnost modelu;
  [MCP](/slovnik/software/mcp/) je protokol, jak nástroje nabídnout
  a zavolat.

## Jak to vypadá

Aplikace dá modelu seznam nástrojů. Například:

```json
{
  "name": "read_file",
  "description": "Přečte textový soubor v povoleném adresáři.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string" }
    },
    "required": ["path"]
  }
}
```

Model odpoví něco jako:

```json
{
  "name": "read_file",
  "arguments": { "path": "smlouva.txt" }
}
```

Aplikace zkontroluje oprávnění, soubor přečte a výsledek pošle zpět.
Teprve pak model vytvoří odpověď pro uživatele.

## Kde se to používá

- **Agentní úlohy** — model si říká o data a akce.
- **Kód** — čtení souborů, spuštění testů, git operace.
- **Dokumenty** — hledání v interních zdrojích.
- **Office** — kalendář, e-mail, tabulky.
- **API** — objednávky, ticketing, CRM.

## Function calling vs. MCP vs. RAG

| Co | Kdo co dělá | Typický příklad |
|---|---|---|
| **Function calling** | model navrhne volání funkce | `read_file("smlouva.txt")` |
| **MCP** | standard pro nabídku a volání nástrojů | klient se připojí k serveru |
| **RAG** | výběr relevantního textu do kontextu | najdi pasáž ve smlouvě |

Function calling a MCP se doplňují: MCP řeší přenos a katalog
nástrojů, function calling řeší, jak o volání požádat.

## Na 128GB boxu

Qwen3.8 Flash Next tool calling podporuje. Ve vLLM se zapíná
přepínači `--enable-auto-tool-choice` a `--tool-call-parser
qwen3_coder`; v llama.cpp záleží na verzi a šabloně. Ověřte, že
engine vrací strukturované volání, ne jen text, který vypadá jako
JSON.

Co ovlivňuje použití:

- **Kontext** — historie volání a výsledky se posílají znovu, takže
  rostou nároky na [KV cache](/slovnik/pamet/kv-cache/).
- **Latence** — každé volání je další kolo modelu; agentní smyčka
  může trvat minuty.
- **Kvalita modelu** — špatné argumenty nebo neexistující nástroj
  jsou častější než u velkých modelů.
- **Parser** — bez správného parseru se strukturovaný výstup rozpadne.

## Rizika

- **Halucinované argumenty** — model pošle cestu nebo ID, které
  neexistuje.
- **Prompt injection** — obsah dokumentu může modelu našeptat jiné
  volání.
- **Příliš široká oprávnění** — nástroj s přístupem k celému disku
  je zbytečně nebezpečný.
- **Nevalidovaný výstup** — aplikace musí ověřit schéma, rozsahy a
  oprávnění, ne věřit modelu.

## Jak zavést tool calling bezpečně

1. Začněte **read-only** nástroji.
2. Definujte **úzké schéma** s povinnými políčky a limity.
3. Validujte argumenty před provedením.
4. Zapište každé volání a výsledek do logu.
5. U zápisu, odeslání a plateb vyžádejte potvrzení člověkem.
6. Testujte i útoky: dokument s pokynem „ignoruj pravidla“.

## Kdy to nemá smysl

- Model má jen odpovídat na text a nic nevolat.
- Úloha jde bezpečně zvládnout skriptem.
- Nemáte čas řešit oprávnění a logy.
