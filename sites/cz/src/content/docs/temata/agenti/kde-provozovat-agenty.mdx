Agent není jen model. Je to **model + nástroje + smyčka + prostředí**.
Tento článek řeší poslední část: kde agent běží, kdo schvaluje jeho
akce a jak se připojí k lokálnímu modelu. Neřeší, v čem se edituje
kód, a neporovnává nástroje velkých poskytovatelů.

## Rychlá odpověď

- **Harness je program, který vede smyčku.** Model rozhoduje,
  harness provádí. Podrobně v [agentním harnessu](/slovnik/software/agent-harness/).
- **Terminál** je nejrychlejší cesta: pi, omp, OpenCode.
- **Desktop** dává přehled a schvalování: OpenChamber, MausBot.
- **Gateway** pustí agenta z chatů: OpenClaw, Hermes.
- **Orchestrace** řeší víc agentů najednou: Herdr.
- **Lokální model** připojíte přes OpenAI kompatibilní endpoint.

## Co je harness a co není

| Vrstva | Co dělá | Příklad |
|---|---|---|
| **Model** | generuje tokeny | Qwen3.8 Flash Next |
| **Engine** | obsluhuje model a API | vLLM, llama.cpp |
| **Harness** | vede smyčku a volá nástroje | pi, omp, OpenCode |
| **Workspace** | ukazuje session a diff | OpenChamber |
| **Nástroj** | čte soubor, spouští test | funkce nebo MCP server |

Harness není model a není engine. Když se rozhoduje o rychlosti,
rozhoduje model a engine. Když se rozhoduje o tom, co agent umí
a co smí, rozhoduje harness.

Nejde o žebříček. Jde o to, kde agent poběží a kdo uvidí jeho

nad ním, desktop pro review.

## Co musí nástroj umět s lokálním modelem

- **OpenAI kompatibilní endpoint** — `/v1/chat/completions`.
- **Tool calling** — model musí umět vrátit strukturované volání.
- **Kontext** — systémový prompt, schémata a historie se musí vejít.
- **Streaming** — jinak čekáte na celou odpověď.
- **MCP nebo vlastní nástroje** — podle úlohy.
- **Logy a schválení** — kdo co spustil.

Když nástroj umí jen chat a ne tool calling, je to chat, ne agent.
Když neumí připojit lokální endpoint, do tohoto článku nepatří.

## Lokální endpoint v praxi

Většina harnessů mluví OpenAI protokolem. Stačí jim base URL,
klíč a model ID:

**Ollama:**

```text
base URL: http://localhost:11434/v1
model: qwen3.5:27b
klíč: nechat prázdné
```

**vLLM:**

```bash
vllm serve Qwen/Qwen3.8-Flash-Next \
  --port 8000 --max-model-len 32768
```

```text
base URL: http://127.0.0.1:8000/v1
model: Qwen/Qwen3.8-Flash-Next
```

**llama.cpp:**

```bash
llama-server -m model.gguf --jinja \
  --host 127.0.0.1 --port 8080 -ngl 999 -c 32768
```

`--jinja` je důležitý: bez něj model nedostane správný chat
template a tool calling se rozpadne. U všech tří platí, že model
musí tool calling opravdu umět; ne každý GGUF ho má.

## Jak vypadá smyčka

1. Harness pošle modelu systémový prompt, historii a schémata
   nástrojů.
2. Model vrátí odpověď, nebo požadavek na nástroj.
3. Harness ověří argumenty a zavolá nástroj.
4. Výsledek přidá do kontextu a pošle modelu.
5. Krok se opakuje, dokud model neodpoví nebo nedojde limit.

Každý krok posílá celou historii znovu. Proto je kontext drahý a
proto se vyplatí ořezávat výstupy nástrojů. Harness, který
posílá 20 nástrojů a celý log, spotřebuje tisíce tokenů ještě
před první užitečnou větou.

## Kontext a tool calling v praxi

Lokální model v harnessu selhává nejčastěji na třech místech:

**1. Chat template.** Model dostane text bez správných značek a
neví, kde je systémová zpráva. U llama.cpp to řeší `--jinja`;
u vLLM se template načte z modelu. Když model odpovídá mimo
formát nebo ignoruje instrukce, začněte tady.

**2. Parser nástrojů.** Model vrátí JSON v textu, ale harness
čeká strukturované volání. Výsledek: agent „odpoví“ místo toho,
aby něco udělal. Pomáhá `tool_choice: required` u extrakce a
správný parser v enginu.

**3. Kontext.** Systémový prompt, schémata a historie se sčítají.
Ilustrativní rozpočet:

| Část | Tokeny |
|---|---:|
| systémový prompt | 1 500 |
| schémata 5 nástrojů | 2 000 |
| historie po 4 krocích | 2 000 |
| nový dotaz | 500 |
| **celkem před odpovědí** | **6 000** |

Do 32k kontextu se to vejde, ale po deseti krocích už ne. Proto
se výstupy nástrojů ořezávají a historie se shrnuje.

**Dobrý test:** jeden nástroj, jedno volání, jasný výsledek.
Teprve potom přidejte druhý nástroj a souběžná volání. Když
model zvládne jedno volání spolehlivě, zvládne i smyčku.

## Terminálové harnessy

### pi

Minimalistický agent v terminálu, MIT, od Earendil Works. Umí
llama.cpp router, Ollama, LM Studio, vLLM i SGLang přes
`models.json`. Silný je v jednoduchosti: snadno se rozšíří a dá se
použít i jako SDK. Podrobnosti v [podstránce pi](/temata/agenti/nastroje/pi/).

### omp

Fork pi od Can Bölüka, MIT, s Rustovým jádrem. Přidává LSP, DAP
(debugger), subagenty, hash-anchored edits a desítky providerů.
Běží nativně na macOS, Linuxu i Windows, vyžaduje Bun. Podrobnosti
v [podstránce omp](/temata/agenti/nastroje/omp/).

### OpenCode

Open-source terminálový coding agent, na kterém stojí OpenChamber.
Podporuje providers včetně lokálních endpointů. Podrobnosti
v [podstránce OpenCode a OpenChamber](/temata/agenti/nastroje/opencode-a-openchamber/).

## Desktopové workspace

### OpenChamber

MIT workspace nad OpenCode. Desktop, web a mobil; multi-run nad
více modely, worktrees, goals, review diffů a remote relay.
Desktop si nese vlastní OpenCode, takže se nic dalšího neinstaluje.
Lokální model jde přes OpenCode. Podrobnosti v
[podstránce OpenCode a OpenChamber](/temata/agenti/nastroje/opencode-a-openchamber/).

### MausBot

Desktop harness s approval kartami, Apache-2.0. Harness poslouchá
na `127.0.0.1`, sessions a klíče drží lokálně. Lokální model
připojí přes OpenAI kompatibilní endpoint. Na Ubuntu vyžaduje
Xorg, Wayland ne. Podrobnosti v
[podstránce MausBot](/temata/agenti/nastroje/mausbot/).

## Gateway

### OpenClaw

Gateway, který zpřístupní agenta z chatů. Umí lokální Ollama
a OpenAI endpoint. Výchozí nastavení shellu je benevolentní;
licence se v dokumentaci rozchází (MIT vs. Apache-2.0). Podrobnosti
v [podstránce OpenClaw](/temata/agenti/nastroje/openclaw/).

### Hermes

Self-hosted asistent a gateway od Nous Research. Připojí libovolný
OpenAI kompatibilní endpoint, včetně Ollama, vLLM a llama.cpp.
Pro agentní práci vyžaduje aspoň 64k kontextu. Má desktop preview,
kanály a schvalování příkazů. Podrobnosti v
[podstránce Hermes](/temata/agenti/nastroje/hermes/).

## Orchestrace

**Herdr** je AI-first multiplexer a orchestrátor. Drží workspaces,
pane a agenty, umí worktrees a CLI/socket API. Sám model neřeší;
spouští pi, omp, OpenCode nebo jiné agenty. Podrobnosti v
[podstránce Herdr](/temata/agenti/nastroje/herdr/).

## Schvalování a oprávnění

Harness se liší hlavně v tom, co udělá **bez ptaní**. Tři vzory:

| Vzor | Co se stane | Kde |
|---|---|---|
| **Bez schválení** | agent spustí, co chce | terminál, důvěryhodný projekt |
| **Schválení u rizika** | shell, zápis, odeslání | desktop, gateway |
| **Schválení vždy** | každá akce | produkce, cizí data |

Pro lokální vývoj v soukromém repu je první vzor přijatelný.
Pro agenta, který vidí firemní dokumenty, je minimum druhý.
Třetí je pro platby a hromadné operace.

Oprávnění nejsou totéž co schválení. Token může být úzký, ale
agent ho použije na něco, co jste nečekali. Proto platí:
**nejmenší token, nejmenší nástroj, nejmenší adresář.**

## Kde která vrstva selhává

| Vrstva | Typická porucha | Jak se pozná |
|---|---|---|
| **Terminál** | model nevolá nástroje | odpovídá textem místo akce |
| **Desktop** | session se ztratí | práce není v diffu |
| **Gateway** | otevřený port | přístup z jiné sítě |
| **Orchestrace** | dva agenti v jednom worktree | konflikty a přepsané soubory |
| **Model** | kontext přeteče | zapomíná začátek nebo končí předčasně |

Vrstvy se neopravují navzájem. Když gateway pustí útočníka,
desktop mu nezabrání. Když orchestrátor špatně přidělí worktree,
sandbox to nespraví.

## Rozhodovací strom

1. **Jeden člověk, jeden projekt** → pi nebo omp v terminálu.
2. **Chci vidět diff a schvalovat** → OpenChamber nebo MausBot.
3. **Chci agenta z telefonu** → OpenClaw nebo Hermes.
4. **Mám víc agentů a worktrees** → Herdr.
5. **Chci jen chat** → žádný harness, stačí model.

Začněte jednou vrstvou. Kombinace přidávejte, až když víte, co
vám chybí.

## Režie a náklady

**Tokeny** (ilustrativní výpočet): systémový prompt 1 500 tokenů,
schémata nástrojů 2 000, historie 1 500 — každý krok posílá
~5 000 tokenů. Osm kroků je 40 000 tokenů kontextu, i když
odpovědi mají jen 3 200 tokenů.

**Čas** (ilustrativní výpočet): 8 kroků × 400 tokenů při 25 tok/s
= 128 s čistého generování. K tomu čtení souborů a testy. Harness
s velkým systémovým promptem přidá sekundy na každý krok.

**Paměť:** harness běží na CPU a bere stovky MB až jednotky GB.
Model a KV cache jsou oddělené. Na 128GB boxu to znamená, že
harness nekonkuruje modelu o GPU, ale může konkurovat o CPU a disk.

## Český příklad: faktury

Firma chce agenta na extrakci faktur. Postup:

1. **Harness:** OpenCode nebo pi v kontejneru bez sítě.
2. **Model:** Qwen3.8 Flash Next přes vLLM na 128GB boxu.
3. **Nástroje:** čtení PDF, OCR, zápis JSON.
4. **Oprávnění:** read-only vstup, výstup do jednoho adresáře.
5. **Schválení:** zápis do účetnictví kartou.
6. **Logy:** kdo, kdy, který dokument, jaký výsledek.

Agent nemá síť, takže injection v PDF nemá kam utéct. Nemá
produkční token, takže nemůže zaúčtovat sám. Když model selže,
člověk to vidí na kartě a opraví.

## Časté chyby

| Chyba | Proč vzniká | Jak se jí vyhnout |
|---|---|---|
| Harness bez tool callingu | „vždyť to je chat“ | ověřit parser a model |
| Příliš mnoho nástrojů | snaha o univerzálnost | 3–5 nástrojů na úlohu |
| Celý log v kontextu | debugging | ořezávat výstupy |
| Agent s osobním tokenem | pohodlí | scoped servisní účet |
| Gateway na veřejném portu | „jen na chvíli“ | localhost nebo VPN |
| Žádný limit kroků | „agent to zvládne“ | 10–20 kroků |
| Testování jen anglicky | model je silnější | česká sada |

## Bezpečnostní minimum

- **Localhost** — gateway ani harness nemá být na veřejném portu.
- **Tokeny** — krátké, úzké, mimo prompt.
- **Schválení** — u zápisu, odeslání a platby.
- **Allowlist nástrojů** — agent vidí jen to, co potřebuje.
- **Logy** — kdo, co, s jakým výsledkem.
- **Kill switch** — okamžité zastavení.

Podrobně to rozebírá [sandbox agentů](/temata/provoz/sandbox-agentu/).

## Kdy použít kterou vrstvu

| Situace | Vrstva | Proč |
|---|---|---|
| Sólový vývojář, jeden repo | terminál | nejrychlejší |
| Návrh změn a review diffu | desktop | přehled a karty |
| Agent z telefonu | gateway | kanály |
| Víc úloh paralelně | orchestrace | worktrees |
| Tým 3–5 lidí | gateway + desktop | přístup a přehled |
| Citlivá data | terminál v sandboxu | nejmenší povrch |

Kombinace nejsou zbytečné, ale mají cenu: každá vrstva přidává
konfiguraci, logy a místo, kde se může pokazit.

## Provoz a údržba

- **Pinujte verze.** Harness, model i engine se mění.
- **Aktualizujte po testu.** Nová verze může změnit tool calling.
- **Sledujte tokeny a chyby.** Nárůst znamená smyčku nebo
  špatný popis nástroje.
- **Zálohujte konfiguraci** a sessions, které potřebujete.
- **Měňte jednu věc najednou.** Model, harness a prompt zároveň
  nejde vyhodnotit.
- **Revize každé tři měsíce.** Nástroje v tomto článku jsou
  mladé; co platilo v listopadu, nemusí platit na jaře.

## Česká specifika

- **Systémový prompt v češtině** může zhoršit tool calling;
  zkuste anglický prompt a český vstup.
- **Diakritika v cestách** k souborům funguje, ale v shellu
  potřebuje správné kódování (UTF-8).
- **Názvy nástrojů** nechte anglicky (`read_file`, `run_test`);
  čeština v schématu může mást.
- **České testovací úlohy** jsou nutné; model může být silný
  v angličtině a slabý v češtině.
- **Formát odpovědi** hlídejte; české modely někdy míchají
  jazyky.

## Checklist před nasazením

- [ ] Model umí tool calling a test prošel.
- [ ] Endpoint je lokální nebo přes VPN.
- [ ] Tokeny jsou krátké a mimo prompt.
- [ ] Nástroje jsou 3–5 a mají validaci.
- [ ] Rizikové akce mají schválení.
- [ ] Je limit kroků a timeout.
- [ ] Logy jsou bez tajemství.
- [ ] Existuje kill switch.
- [ ] Je záložní plán, když model selže.
- [ ] Někdo ví, kdo to provozuje.

## Co tu nenajdete

Tento článek je o **běhu agenta**, ne o editorech, pluginech do
editorů, cloudu ani o nástrojích velkých poskytovatelů. Ty jsou
jiná kategorie a mají jiná pravidla. Pokud je používáte, tento
text vám je nevyvrátí; jen říká, že lokální cesta jde i bez nich.

## Kdy to nepoužívat

- **Když stačí chat** — harness je zbytečná vrstva.
- **Když nemáte čas na údržbu** — nástroje se mění po měsících.
- **Když agent potřebuje produkční klíče** — nejdřív oprávnění.
- **Když nástroj neumí lokální endpoint** — nepatří sem.
- **Když chcete jen „AI v editoru“** — to je jiná kategorie.
