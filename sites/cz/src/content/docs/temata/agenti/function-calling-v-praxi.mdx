**Function calling** je schopnost modelu požádat o zavolání funkce.
V praxi to znamená, že model vrátí strukturovaný požadavek a vaše
aplikace ho provede. Rozhoduje návrh schématu, parser a validace,
ne jen model.

## Rychlá odpověď

- **Model navrhne, aplikace provede.** Nikdy nenechte model volat
  přímo bez validace.
- **Schéma držte úzké** — méně polí, jasné typy, povinné údaje.
- **Ve vLLM zapněte tool parser** a ověřte, že výstup je strukturovaný.
- **Každé volání logujte** a u citlivých akcí vyžádejte potvrzení.

## Schéma

Dobré schéma:

- **má málo polí**,
- **používá enum** pro volby,
- **označí povinná pole**,
- **má limity** (délka, rozsah),
- **neposkytuje** volný text tam, kde má být číslo.

Příklad:

```json
{
  "name": "read_file",
  "description": "Přečte textový soubor v povoleném adresáři.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": { "type": "string" }
    },
    "required": ["path"]
  }
}
```

## vLLM

Qwen3.8 Flash Next používá ve vLLM přepínače:

```bash
--enable-auto-tool-choice
--tool-call-parser qwen3_coder
```

Bez parseru může model vrátit text, který vypadá jako JSON, ale není
to strukturované volání. Ověřte to na jednoduchém nástroji.

## Validace a retry

1. **Zkontrolujte JSON** — parsovatelnost a typy.
2. **Zkontrolujte povinná pole.**
3. **Zkontrolujte rozsahy** — čísla, délky, enum.
4. **Zkontrolujte oprávnění** — smí uživatel tuhle akci?
5. **Při chybě** vraťte modelu konkrétní chybu a nechte ho opravit.
6. **Po dvou chybách** se zeptejte člověka.

## Tool choice

- **Auto** — model se rozhodne, kdy nástroj použít.
- **Required** — musí zavolat nástroj; hodí se pro extrakci.
- **None** — nástroje jsou dostupné, ale model je nemá použít.

Pro extrakci je `required` užitečné. Pro chat může být `auto`
přirozenější.

## Latence a kontext

Každé volání je další kolo modelu. Historie a výstupy nástrojů rostou,
takže:

- **prefill** se prodlužuje,
- **KV cache** zabírá víc paměti,
- **celý úkol** může trvat minuty.

U agenta proto omezujte počet kroků a velikost výstupů nástrojů.

## Testování

- **Správné volání** — model vybere nástroj a argumenty.
- **Chybějící pole** — aplikace odmítne.
- **Neexistující soubor** — nástroj vrátí chybu, model ji zpracuje.
- **Neoprávněná akce** — aplikace odmítne.
- **Injection v dokumentu** — model nesmí poslechnout.
- **Dlouhý výstup** — musí se oříznout.

## Příklad: extrakce faktury

Model dostane nástroj `uloz_fakturu` se schématem pro dodavatele,
IČO, částku a datum. Výstup se validuje; když chybí IČO, aplikace
volání odmítne a vrátí modelu chybu. Model se zeptá nebo pole označí
jako chybějící. Nikdy neuloží vymyšlené IČO.

## Jak vypadá odpověď modelu

Model nevolá funkci přímo, vrací požadavek:

```json
{
  "tool_calls": [
    {
      "name": "read_file",
      "arguments": { "path": "smlouvy/2026/ramcova-smlouva.pdf" }
    }
  ]
}
```

Aplikace ověří oprávnění, zavolá funkci a vrátí výsledek jako další
zprávu. Teprve pak model pokračuje. Když odpověď obsahuje `content`
místo `tool_calls`, model nástroj nezavolal — často proto, že chybí
parser nebo je špatně popsaný nástroj.

## Kolik kroků agent zvládne

Každý krok přidá do kontextu výstup nástroje. Ilustrativní **výpočet**:
pět kroků po 1 500 tokenech výstupu je 7 500 tokenů navíc, k tomu
systémový prompt, historie a schémata. Na 32k kontextu to znamená,
že po šesti až osmi krocích dochází místo.

Proto se v praxi nastavuje:

- **maximální počet kroků** (např. 10) a jasná chyba, když se vyčerpá,
- **limit velikosti výstupu nástroje**, aby jeden výsledek nesežral
  celý kontext,
- **shrnutí historie** u dlouhých úloh.

Agent, který běží 40 kroků, není důkaz kvality. Často je to známka,
že se zacyklil.

## Časté chyby

| Chyba | Projev | Oprava |
|---|---|---|
| Popis nástroje je vágní | model volá špatný nástroj | napsat, kdy nástroj použít a kdy ne |
| Schéma povoluje volný text | argumenty nejdou parsovat | omezit typy a použít enum |
| Chybí `required` | prázdné argumenty | označit povinná pole |
| Aplikace nevaliduje | uloží vymyšlené IČO | validace a návrat chyby modelu |
| Výstup nástroje je obrovský | kontext se zaplaví | oříznout, stránkovat |
| Akce bez potvrzení | nevratný zápis | potvrzení člověkem |

## Kdy to nedělat

- Model má jen odpovídat textem.
- Úloha jde bezpečně zvládnout skriptem.
- Nemáte validaci a logy.
- Akce je nevratná a bez potvrzení.
