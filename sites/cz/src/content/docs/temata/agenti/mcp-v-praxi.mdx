**MCP** je praktický způsob, jak modelu nabídnout nástroje, aniž byste
pro každou aplikaci psali vlastní integraci. Server nástroje popíše,
klient je nabídne modelu a model o volání požádá. Zbytek je oprávnění
a disciplína.

## Rychlá odpověď

- **MCP server = nabídka nástrojů.** Klient = aplikace, která model
  spouští.
- **Začněte read-only** serverem nad jedním adresářem.
- **Oprávnění a sandbox** jsou důležitější než počet nástrojů.
- **Testujte i útoky** — dokument s podvrženým pokynem.

## Architektura

| Část | Co dělá | Příklad |
|---|---|---|
| **Klient** | spouští model, přijímá volání | chat, IDE, agent |
| **Server** | nabízí nástroje a data | soubory, git, DB |
| **Model** | rozhoduje, co zavolat | Qwen3.8 Flash Next |
| **Aplikace** | volání provede a vrátí výsledek | váš kód |

Server může běžet lokálně (`stdio`) nebo jako síťová služba. Lokální
varianta je pro citlivá data přirozenější.

## První server

Začněte jedním z těchto:

- **soubory** — čtení v povoleném adresáři,
- **git** — historie, diff, větve,
- **SQLite** — dotazy nad jednou databází,
- **dokumentace** — hledání v Markdownu.

Nepřidávejte hned zápis, mazání a e-mail. Nejdřív ověřte, že model
volá správné nástroje.

## Oprávnění

- **Allowlist adresářů** — jen konkrétní složka.
- **Read-only** — žádný zápis, dokud nemáte jistotu.
- **Žádné klíče v promptu** — tokeny patří do prostředí.
- **Limity** — maximální počet volání a velikost výstupu.
- **Logy** — kdo co zavolal.

Server, který vidí celý disk, je zbytečně nebezpečný.

## Testování

1. **Seznam nástrojů** — model vidí jen povolené.
2. **Čtení známého souboru** — vrátí správný obsah.
3. **Pokus mimo allowlist** — musí selhat.
4. **Dokument s injection** — model nesmí poslechnout.
5. **Dlouhý výstup** — musí se oříznout.
6. **Restart** — server se zotaví.

## Provoz

- **Verzujte konfiguraci** serveru.
- **Logujte** každé volání a výsledek.
- **Aktualizujte** server i klienta.
- **Omezujte** počet nástrojů; méně je bezpečnější.
- **Mějte kill switch** — možnost agenta zastavit.

## Příklad: git server

Agent dostane úkol „vysvětli, co změnil poslední commit“. MCP server
nabídne nástroje `git_log` a `git_diff`, oba read-only. Model si vyžádá
diff, přečte ho a odpoví. Nemá nástroj pro push ani pro přístup k
produkční větvi. To je bezpečný starting point.

## Jak vypadá jedno volání

1. Uživatel napíše úkol.
2. Klient pošle modelu zprávu a **seznam nástrojů** se schématy.
3. Model vrátí požadavek na volání (`tool`, argumenty).
4. **Aplikace** volání provede — ne model.
5. Výsledek se vrátí modelu jako další zpráva.
6. Model odpoví, nebo požádá o další volání.

Klíčové je, že **model nic nevykonává**. Kdyby vykonával, nemohli
byste nic omezit. Veškerá bezpečnost je v krocích 4 a 5.

## Kolik nástrojů je moc

Každý nástroj je popis se schématem, který letí v **každém** požadavku.
Když jich máte padesát, model jich půlku ignoruje a zbytek plete.

Ilustrativní **výpočet**: nástroj s popisem a schématem zabere
kolem 200 tokenů; dvacet nástrojů je 4 000 tokenů, které se posílají
při každém dotazu a zabírají kontext. Čísla se liší podle schématu,
ale princip platí: **méně nástrojů = přesnější volání a levnější
provoz**.

Pro začátek stačí 3–5 nástrojů, které pokryjí jeden pracovní postup.

## Když model volá špatný nástroj

| Příznak | Příčina | Co udělat |
|---|---|---|
| Volá nástroj, který neexistuje | slabý popis nebo halucinace | zpřesnit popis, omezit počet |
| Plete dva podobné nástroje | překrývající se názvy | sloučit je, nebo přejmenovat |
| Posílá prázdné argumenty | chybí povinná pole ve schématu | označit `required` |
| Volá pořád dokola | nemá výsledek nebo signál konce | omezit počet volání |
| Odpoví bez volání | úkol je popsaný jako chat | upravit systémový prompt |
| Volá se špatnými daty | žádná validace v aplikaci | validovat a vrátit chybu modelu |

Chybu nikdy neřešte tím, že dáte modelu víc nástrojů. Většinou
pomůže míň nástrojů a lepší popis.

## Nasazení pro tým

`stdio` server je vázaný na jednu aplikaci a jednoho uživatele. Pro
tým potřebujete síťový server s autentizací, jinak se oprávnění
obchází. Platí stejná pravidla jako u [API serveru](/temata/provoz/api-server/):
TLS, token, logy a rate limit.

## Kdy MCP nepotřebujete

- Jeden skript, který běží jednou.
- Chat bez nástrojů.
- Úloha, kterou zvládne obyčejné API.
- Nemáte čas řešit oprávnění a logy.
