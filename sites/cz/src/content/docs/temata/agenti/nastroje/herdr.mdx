**Herdr** je terminálový multiplexer a orchestrátor pro coding
agenty. Není to harness ani model; je to vrstva, která spouští
víc agentů, předává jim úkoly a drží session. Lokální model řeší
agent, kterého Herdr spustí. Pojem vysvětluje
[orchestrace agentů](/slovnik/software/orchestrace-agentu/).

## Rychlá odpověď

- **Apache-2.0, macOS/Linux, Windows v preview.**
- **Není model layer.** Lokální model závisí na agentovi.
- **Workspaces, panes, agents** — tři primitiva.
- **Worktrees** pro izolaci paralelních úloh.
- **CLI a socket API** pro skriptování a orchestrace.

## Co to je

Herdr vypadá jako tmux, ale rozumí agentům. Místo slepého
terminálu ví, jestli agent pracuje, čeká nebo selhal. Můžete mu
poslat prompt, počkat na výsledek a přečíst odpověď — z CLI nebo
z jiného agenta.

Tři primitiva:

| Pojem | Co to je |
|---|---|
| **Workspace** | jeden projekt nebo úloha |
| **Pane** | skutečný shell pro agenta, test nebo server |
| **Agent** | rozpoznaný proces, který Herdr umí adresovat |

## Připojení lokálního modelu

Herdr sám model nevybírá. Spustíte v něm agenta, který lokální
model umí:

- [pi](/temata/agenti/nastroje/pi/) s llama.cpp routerem,
- [omp](/temata/agenti/nastroje/omp/) s Ollama nebo vLLM,
- [OpenCode](/temata/agenti/nastroje/opencode-a-openchamber/) s
  OpenAI kompatibilním endpointem.

Tím se Herdr stává orchestrací lokálních agentů, ne dalším
modelem.

## Instalace

1. Nainstalujte Herdr podle dokumentace.
2. Otevřete workspace v projektu.
3. Spusťte agenta v pane.
4. Ověřte, že Herdr agenta rozpozná a vidí jeho stav.
5. Přidejte druhý pane nebo worktree.

Příkazy se mohou mezi verzemi měnit; používejte dokumentaci
konkrétní verze.

## Workflow

1. Vytvořte workspace pro úlohu.
2. Spusťte agenta a zadejte cíl.
3. Agent běží v pane; Herdr sleduje stav.
4. Pomocníka spustíte v dalším pane nebo worktree.
5. Výsledek vrátíte hlavnímu agentovi.
6. Hotové panes zavřete; worktrees ukliďte.

Pro paralelní práci je klíčové, že každý agent má vlastní
worktree. Jinak si agenti přepíšou soubory.

## Worktree v praxi

1. Hlavní workspace drží projekt.
2. Druhý agent dostane vlastní worktree a branch.
3. Pracuje na izolované kopii.
4. Výsledek se reviewuje a merguje.
5. Worktree se smaže.

Bez worktree dva agenti editují stejný soubor a výsledek je
nedeterministický. Herdr worktrees umí, ale musíte je použít;
samotné panes izolaci souborů nedávají.

## CLI a socket

Herdr je skriptovatelný. Z CLI nebo socketu můžete:

- vytvořit workspace a pane,
- spustit agenta a poslat mu prompt,
- počkat na stav,
- přečíst výstup,
- poslat další instrukci,
- zastavit agenta.

To je užitečné pro orchestraci: jeden agent může spustit
pomocníka, počkat na výsledek a pokračovat. Zároveň to znamená,
že kdokoli s přístupem k socketu může ovládat běžící agenty.

## Limity

- **Žádná izolace.** Herdr je multiplexer, ne sandbox; agenti
  běží jako vy. Na rizikový kód použijte kontejner.
- **Žádný model layer.** Když agent lokální model neumí, Herdr
  to nespraví.
- **Windows preview.** Na Windows může být chování jiné.
- **Složitost.** Víc agentů znamená víc session a víc úklidu.

## Bezpečnost

- **Agenti dědí vaše oprávnění.** Nevkládejte produkční klíče.
- **Worktree není sandbox.** Chrání soubory, ne systém.
- **Příkazy z CLI** mohou ovlivnit běžící agenty.
- **Logy** a výstupy mohou obsahovat citlivá data.

## Kdy to nepoužít

- Když máte jednoho agenta a jednu úlohu.
- Když chcete bezpečnostní izolaci — použijte sandbox.
- Když nemáte čas uklízet worktrees.
- Když agent neumí lokální model.
