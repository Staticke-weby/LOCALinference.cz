**omp** (oh my pi) je terminálový coding agent, který vznikl jako
fork **pi**. Přidává LSP, debugger, subagenty a hash-anchored
edits. Zůstává open source a umí lokální modely.

## Rychlá odpověď

- **MIT, terminál, macOS/Linux/Windows.** Vyžaduje Bun 1.3.14+.
- **Lokální model:** Ollama, LM Studio, llama.cpp, vLLM.
- **Silná stránka:** LSP a DAP v terminálu, subagenti, worktrees.
- **Slabina:** mladý projekt, hodně možností, rychlý vývoj.

## Co to je

omp rozšiřuje pi o věci, které obvykle řeší IDE:

- **LSP** — diagnostika, symboly, rename napříč projektem.
- **DAP** — připojení skutečného debuggeru.
- **Subagenti** — rozdělení práce na víc běhů.
- **Hash-anchored edits** — úprava podle hashů řádků, méně
  nepovedených patchů.
- **Worktrees** — izolace paralelních úloh.

Není to náhrada IDE. Je to agent, který se chová víc jako IDE.

## Připojení lokálního modelu

Podle dokumentace a recenzí funguje stejná cesta jako u pi:

- **Ollama** na `http://localhost:11434/v1`,
- **LM Studio** na svém OpenAI endpointu,
- **llama.cpp server** s `--jinja`,
- **vLLM** s OpenAI API.

Konfigurace je v `~/.omp/agent/models.yml` (models) a
`~/.omp/agent/settings.yml` (nástroje a chování). Přesné položky
se mohou mezi verzemi změnit; ověřte je proti aktuální dokumentaci.

Pro lokální model platí: čím lepší tool calling, tím méně
opravných smyček. omp umí model vyměnit uprostřed session.

## Instalace

```bash
curl -fsSL https://omp.sh/install | sh
```

Homebrew: `brew install can1357/tap/omp`. Přes Bun:
`bun install -g @oh-my-pi/pi-coding-agent`. Windows PowerShell:
`irm https://omp.sh/install.ps1 | iex`.

Po instalaci spusťte `omp` v projektu. Doporučené je doplnit
shell completions.

## Workflow

1. `cd` do projektu a spusťte `omp`.
2. `/login` vybere providera, `/model` model.
3. Agent čte repo, používá LSP a navrhuje změny.
4. Subagenti řeší části úlohy paralelně.
5. `review` nebo ruční kontrola diffu.
6. Worktree izoluje rizikové změny.

Pro orchestraci víc agentů se omp často kombinuje s
[Herdr](/temata/agenti/nastroje/herdr/).

## LSP a DAP v praxi

**LSP** dává agentovi stejné informace jako editor: diagnostiku,
symboly, reference a rename. Když agent přejmenuje funkci, projde
to přes jazykový server a upraví i re-exporty a aliasy. Méně
„skoro správných“ patchů.

**DAP** připojí skutečný debugger. Agent může zastavit proces,
projít zásobník a přečíst proměnné. Hodí se na chyby, které
z kódu nepoznáte.

Obojí závisí na jazykovém serveru a debuggeru pro daný jazyk.
Pro neznámý jazyk to nebude fungovat.

## Subagenti

Subagent je samostatný běh s vlastním kontextem. Používá se na:

- paralelní review,
- rozdělení velké úlohy,
- testování variant,
- práci v samostatném worktree.

Výhoda je izolace kontextu; nevýhoda je, že subagent nevidí
všechno, co hlavní agent. Je potřeba mu dát přesný brief a
výsledek zkontrolovat.

## Limity

- **Bun.** Bez něj instalace neprojde.
- **Mladý projekt.** Chování a config se mění.
- **Příliš možností.** Některé volby je potřeba vypnout, jinak
  agent dělá víc, než chcete.
- **LSP závisí na jazyce.** Pro každý jazyk potřebujete server.
- **Model.** Lokální model nemusí zvládnout složité refaktoringy.

## Bezpečnost

omp spouští příkazy a edituje soubory jako vy. Subagenti a
worktrees pomáhají s izolací, ale nejsou bezpečnostní hranice.
Na nedůvěryhodný kód použijte [sandbox](/temata/provoz/sandbox-agentu/).

## Kdy to nepoužít

- Když chcete jednoduchý nástroj bez konfigurace.
- Když nemáte Bun a nechcete ho instalovat.
- Když potřebujete stabilní API dlouhodobě.
- Když model neumí tool calling.
