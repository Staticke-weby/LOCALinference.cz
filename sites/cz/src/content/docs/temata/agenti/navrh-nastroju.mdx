**Návrh nástroje** rozhoduje, jestli agent udělá správnou věc.
Model vidí jen název, popis a schéma; když jsou vágní, volá
špatně. Nástroj není skript pro člověka, je to rozhraní pro model.

## Rychlá odpověď

- **Málo nástrojů, jasné názvy.** 3–5 na úlohu.
- **Schéma úzké** — typy, enum, povinná pole.
- **Chyba musí být srozumitelná** a bezpečná.
- **Oprávnění a validace jsou v aplikaci**, ne v promptu.

## Anatomie nástroje

| Část | Co musí říct |
|---|---|
| **Název** | sloveso a objekt: `read_file`, `search_invoices` |
| **Popis** | kdy použít a kdy ne |
| **Parametry** | typy, rozsahy, povinnost |
| **Výstup** | struktura a limity |
| **Chyby** | co znamenají a co s nimi |

Popis „provede operaci“ je k ničemu. Popis „přečte textový
soubor v povoleném adresáři; použij, když potřebuješ obsah
souboru“ modelu pomůže.

## Schéma v praxi

```json
{
  "name": "read_file",
  "description": "Přečte textový soubor v adresáři projektu. Nepoužívej pro binární soubory.",
  "parameters": {
    "type": "object",
    "properties": {
      "path": {
        "type": "string",
        "description": "Relativní cesta v projektu"
      }
    },
    "required": ["path"],
    "additionalProperties": false
  }
}
```

`additionalProperties: false` zabrání modelu posílat vymyšlené
parametry. Enum používejte pro volby, ne volný text.

## Chyby a idempotence

- **Konkrétní chyba** — „soubor neexistuje“, ne „error 500“.
- **Bezpečná chyba** — neprozradí interní cesty ani klíče.
- **Idempotence** — opakované volání nesmí zdvojit platbu.
- **Dry-run** — akce se dá vyzkoušet bez následku.
- **Timeout** — nástroj nesmí viset věčně.

Když model dostane nejasnou chybu, zkusí to znovu a jinak. Když
dostane přesnou, opraví argument.

## Oprávnění

- **Allowlist adresářů** — nástroj vidí jen projekt.
- **Read-only** pro čtení.
- **Scoped token** pro zápis.
- **Potvrzení** u odeslání a platby.
- **Limit** počtu volání.

Nástroj, který umí všechno, je horší než tři úzké. Model se
v širokém rozhraní ztratí a vy nemáte jak omezit následek.

## MCP server

MCP je standard, jak nástroje nabídnout. Server popíše nástroje
a klient je předá modelu. Platí stejná pravidla:

- **malý počet nástrojů**,
- **validace na serveru**,
- **žádné klíče v popisu**,
- **logy každého volání**,
- **sandbox** pro soubory a síť.

MCP není bezpečnostní vrstva. Je to protokol; oprávnění řeší
server a aplikace.

## Špatný a dobrý popis

Porovnejte dvě verze stejného nástroje:

```text
# špatně
name: process
description: Provede operaci se souborem.

# dobře
name: read_text_file
description: Přečte UTF-8 textový soubor v adresáři projektu.
  Použij, když potřebuješ obsah souboru. Nepoužívej pro PDF
  ani binární soubory; na ty použij extract_pdf.
```

Druhá verze říká, co nástroj dělá, kdy ho použít a co místo
něj zvolit jindy. Model pak nesahá po `process` na všechno.

## MCP, nebo vlastní funkce

- **MCP server** — když nástroj používá víc klientů nebo
  ho chcete oddělit od aplikace.
- **Vlastní funkce** — když je nástroj úzce svázaný s aplikací
  a běží ve stejném procesu.

MCP přidává proces, konfiguraci a další místo, kde může dojít
k chybě. Pro tři nástroje v jedné aplikaci je často zbytečný.

## Testování

1. Správné volání na známém vstupu.
2. Chybějící parametr.
3. Neplatný typ.
4. Cesta mimo allowlist.
5. Neexistující soubor.
6. Dlouhý výstup.
7. Opakované volání.
8. Injection v dokumentu.

## Příklad: fakturační nástroj

Místo `process_invoice` udělejte tři úzké nástroje:

| Nástroj | Co dělá | Riziko |
|---|---|---|
| `read_invoice` | přečte PDF a vrátí text | nízké |
| `extract_fields` | vrátí JSON podle schématu | střední |
| `post_invoice` | zapíše do účetnictví | vysoké, potvrzení |

Model tak nemůže „rovnou zaúčtovat“. Musí projít extrakcí,
validací a potvrzením. Když extrakce selže, `post_invoice` se
nikdy nezavolá.

Pro `post_invoice` použijte idempotentní klíč (číslo faktury),
aby opakované volání nezdvojilo zápis.

## Časté chyby

| Chyba | Proč vzniká | Jak se jí vyhnout |
|---|---|---|
| Jeden nástroj na všechno | rychlost vývoje | rozdělit podle rizika |
| Vágní popis | „vždyť to je jasné“ | napsat, kdy použít a kdy ne |
| Chybí `required` | spěch | označit povinná pole |
| Chyba bez detailu | obecný error | konkrétní a bezpečná zpráva |
| Bez limitu výstupu | velký soubor | oříznout a stránkovat |
| Bez logu | „netřeba“ | logovat nástroj a výsledek |

## Kdy to neřešit

- Když agent jen odpovídá textem.
- Když stačí jeden skript.
- Když nemáte čas na validaci.
- Když nástroj sahá na produkční data bez oprávnění.
