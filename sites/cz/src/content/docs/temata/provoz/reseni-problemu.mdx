Většina problémů s lokální AI má čtyři příčiny: model se nevešel,
engine nevidí GPU, stroj se přehřívá, nebo je špatně nastavený
kontext. Než začnete měnit model, zjistěte, která z nich to je.
Tabulky níže jsou od nejčastějšího k nejvzácnějšímu.

## Rychlá odpověď

- **Nejdřív zkontrolujte GPU**, ne model: `nvidia-smi`, `rocminfo`
  nebo `system_profiler`.
- **Z logu enginu hledejte `cuda`, `rocm` nebo `metal`.** Když tam
  není, běží výpočet na procesoru.
- **Pomalý běh po pár minutách** je obvykle [throttling](/slovnik/provoz/throttling/),
  ne slabý model.
- **Špatná kvalita** bývá kvantizace, teplota vzorkování nebo špatný
  chat template, ne „hloupý model“.

## Nejdřív: běží model na GPU?

| Platforma | Příkaz | Co hledat |
|---|---|---|
| NVIDIA (DGX, RTX) | `nvidia-smi` | název karty, driver, využité MiB |
| AMD (Strix Halo) | `rocminfo` | agent s `gfx1151` |
| Apple | `system_profiler SPDisplaysDataType` | čip a počet jader |
| Engine | log při startu | `cuda`, `rocm`, `metal`, nebo `cpu` |

Když log hlásí `cpu`, je to nejčastější příčina „pomalého modelu“.
Engine funguje, jen nevidí grafiku — obvykle kvůli špatnému balíčku
PyTorche nebo ovladači.

## Model se nespustí

| Příznak | Příčina | Co udělat |
|---|---|---|
| `out of memory` při načtení | model + KV cache se nevešly | zkratit kontext, nižší kvantizace, menší batch |
| `unknown model architecture` | starý engine | aktualizovat [vLLM](/slovnik/software/vllm/) nebo [llama.cpp](/slovnik/software/llamacpp/) |
| `no kernel image is available` | torch nesedí na architekturu | přeinstalovat torch pro správnou CUDA |
| `permission denied` na soubory modelu | špatná práva | opravit vlastníka a práva |
| start trvá mnoho minut | načítání z pomalého disku | model na NVMe, ne na síťovém disku |
| `CUDA error: driver too old` | ovladač starší než runtime | aktualizovat ovladač |

U [DGX Sparku](/zarizeni/dgx-spark/) je oficiální cesta kontejner
NVIDIA; mimo něj se mohou rozcházet verze CUDA a ovladače. Držte se
[návodu](/navody/dgx-spark/), ne blogových receptů.

## Běží pomalu

| Příznak | Příčina | Co udělat |
|---|---|---|
| desítky sekund na token | výpočet na CPU | zkontrolovat GPU v logu |
| rychlost po minutě klesne | [throttling](/slovnik/provoz/throttling/) | zlepšit chlazení, snížit [power limit](/slovnik/provoz/power-limit/) |
| první odpověď trvá dlouho, pak je to rychlé | prefill dlouhého promptu | zkrátit kontext, zapnout [prefix caching](/slovnik/pamet/prefix-caching/) a [flash attention](/slovnik/software/flash-attention/) |
| s každým uživatelem pomaleji | fronta a KV cache | omezit souběžnost, sledovat [monitoring](/temata/provoz/monitoring/) |
| mnohem pomalejší než tabulky | jiná kvantizace nebo kontext | porovnat konfiguraci, ne jen model |

Než začnete řešit, spočítejte si [roofline](/rychlost/roofline/): když
naměřené číslo převyšuje teoretický strop, je měření špatně; když je
hluboko pod ním, brzdí něco jiného než paměť.

## Odpovídá špatně

| Příznak | Příčina | Co udělat |
|---|---|---|
| opakuje se, nedrží formát | teplota vzorkování | snížit teplotu, omezit max tokens |
| nerozumí systému promptu | chat template | použít template z model cardu |
| míchá jazyky | slabá kvantizace | zkusit vyšší přesnost |
| ztrácí informace uprostřed | [context rot](/slovnik/pamet/context-rot/) | kratší kontext, RAG |
| vymýšlí nástroje | function calling | ověřit schéma a formát odpovědi |

## Podle platformy

| Platforma | Typický problém | Kde hledat |
|---|---|---|
| Windows x64 | CPU fallback, ovladač | `nvidia-smi`, log ComfyUI |
| Windows on Arm | chybí ARM64 wheel | build ze zdroje, nebo node vynechat |
| DGX OS | verze CUDA mimo kontejner | oficiální kontejner NVIDIA |
| Strix Halo | ROCm a `gfx1151` | `rocminfo`, [ROCm](/slovnik/software/rocm/) |
| macOS | MPS vs. CPU | `mlx-lm`, log enginu |

Na Windows on Arm se problémy projevují hlavně u vlastních nodes
v ComfyUI: část balíčků nemá ARM64 wheel a instalace skončí chybou.
[Recept pro Windows](/generovani/recepty/windows/) vypisuje konkrétní
balíčky, které NVIDIA jmenuje.

Na Strix Halu je nejčastější příčinou kombinace ovladače a verze
ROCm. Když `rocminfo` kartu vidí, ale engine ne, je problém
v runtime, ne v hardwaru.

## Co poslat podpoře

Když se problém nepodaří vyřešit, pošlete tři věci místo popisu
„nejde to“:

1. **Příznak** — přesná hláška nebo číslo, ne dojem.
2. **Prostředí** — zařízení, OS, verze enginu a ovladače.
3. **Konfigurace** — model, kvantizace, kontext, batch, příkaz.

Bez těchto údajů nejde problém zopakovat a odpověď bude odhad.

## Kde je limit

- **Ne každý problém je v modelu.** Většina je v konfiguraci.
- **Aktualizace může zhoršit.** Pinujte verze, které fungují.
- **Throttling se nepozná z jednoho čísla.** Sledujte průběh.
- **Komunitní recepty stárnou.** Ověřujte datum a verzi.
