Lokální AI se mění: nové verze vLLM, llama.cpp, ovladačů a modelů.
Aktualizace může zlepšit rychlost, ale také rozbít API nebo změnit
chování. Bez pinovaných verzí a rollbacku se z provozu stane
experiment.

## Rychlá odpověď

- **Pinujte verze** modelu, enginu, ovladačů a konfigurace.
- **Testujte ve stagingu**, ne na produkci.
- **Mějte rollback** a zálohu konfigurace.
- **Zapisujte změny** a důvod.

## Co pinovat

| Co | Proč |
|---|---|
| **Model** | jiná revize může mít jiné chování |
| **Kvantizace** | NVFP4/FP8/GGUF se liší |
| **Engine** | vLLM/llama.cpp verze mění API |
| **Ovladače** | CUDA/ROCm ovlivní výkon |
| **OS** | DGX OS, Ubuntu, Windows |
| **Konfigurace** | teplota, kontext, MTP, KV cache |

Pinujte konkrétní revizi nebo tag, ne „latest“.

## Postup aktualizace

1. **Přečtěte changelog** a známé problémy.
2. **Zálohujte** konfiguraci a data.
3. **Nasaďte do stagingu** se stejnou konfigurací.
4. **Spusťte testy** — API, kvalita, výkon, paměť.
5. **Porovnejte s baseline.**
6. **Nasaďte na produkci** v okně s nízkým provozem.
7. **Sledujte** metriky a chyby.
8. **Při problému rollback.**

## Testy

- **Health check** a základní prompt.
- **Tool calling** a parser.
- **Dlouhý kontext** a KV cache.
- **Souběžnost** 2–4 požadavky.
- **Kvalita** na vašich úlohách.
- **Paměť** a teplota.

Bez testů je aktualizace jen naděje.

## Zálohy

- **Konfigurace** — YAML, příkazy, proměnné.
- **Model** — revize a hash; samotné váhy se dají stáhnout.
- **Data** — dokumenty, index, databáze.
- **Logy** — pro audit.
- **Postup obnovy** — vyzkoušený, ne jen popsaný.

## Rollback

- **Předchozí image** nebo binárka.
- **Předchozí revize modelu.**
- **Předchozí konfigurace.**
- **Ověření**, že API a data fungují.

Rollback musí být rychlý. Když trvá hodiny, není to rollback.

## Příklad: rollback

Nová verze vLLM zhorší tool calling. Ve stagingu testy projdou, ale
v produkci agent přestane volat nástroj. Rollback na předchozí image
a konfiguraci vrátí provoz do stavu před aktualizací. Bez pinované
verze byste nevěděli, kam se vrátit.

## Matice rizika

Ne každá aktualizace je stejně nebezpečná. Rozhodujte podle toho, co
se mění:

| Co aktualizujete | Riziko | Test | Rollback |
|---|---|---|---|
| Model (nová revize) | vysoké | kvalita a tool calling | předchozí revize |
| Engine (vLLM, llama.cpp) | vysoké | API, výkon, paměť | předchozí image |
| Ovladač CUDA/ROCm | střední | výkon, stabilita | předchozí ovladač |
| OS | vysoké | vše | snapshot |
| Konfigurace promptu | nízké | 20 úloh | git |
| Vektorový index | střední | Recall@5 | přegenerování |

Čím blíž je vrstva modelu, tím horší je rollback. U modelu se proto
měsíce pinuje revize a mění se vědomě, ne při každém vydání.

## Kdy aktualizovat hned

- **Bezpečnostní oprava** ovladače nebo enginu.
- **Kritická chyba**, která se vás týká.
- **Nekompatibilita** s novým klientem nebo API.

Naopak „vyšla nová verze“ není důvod. Provoz, který funguje, nemá
smysl měnit v pátek odpoledne.

## Checklist

- [ ] Jsou verze pinované?
- [ ] Je staging?
- [ ] Jsou testy?
- [ ] Je záloha?
- [ ] Je rollback?
- [ ] Je changelog?
- [ ] Je okno nasazení?
- [ ] Je monitoring?

## Kdy neaktualizovat

- Před důležitým provozem.
- Bez zálohy a rollbacku.
- Bez testů.
- Když changelog neznáte.
- Když nemáte čas řešit problémy.
