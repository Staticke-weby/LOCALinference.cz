Tento návod platí pro **RTX Spark mini i notebook** — mají stejný
Windows 11 Arm64, stejný CUDA stack a stejný postup. Rozdíl je jen
v chlazení a baterii: notebook nechte při prvním nastavení na nabíječce.

> **Co budete potřebovat:** Windows 11 Arm64, NVIDIA driver kompatibilní
> s CUDA 13.4, ARM64 Python 3.13, místo na model (desítky GB) a dalších
> 32 GB na NVMe pro PLE cache.

**Dvě věci narovinu, než začnete:**

- **Model je od NVIDIA** — `nvidia/Qwen3.8-Flash-Next-FP4-Local` na
  Hugging Face. To je odladěná NVFP4 varianta pro 128GB GB10 stroje.
- **vLLM build je komunitní** — projekt `devjeonghwan/vllm-for-rtx-spark`
  připravuje ARM64 kolo vLLM s MTP a CUDA grafy. Není to oficiální
  Windows build od vLLM ani od NVIDIA. Čísla níže jsou od autora
  projektu, ne naše.

## Krok 1: Windows, ovladače a paměť

1. **Settings → Windows Update** a nainstalujte všechny aktualizace.
2. Nainstalujte nejnovější **NVIDIA driver pro RTX Spark** z
   [nvidia.com/drivers](https://www.nvidia.com/en-us/drivers/) a
   restartujte.
3. Ověřte, že Windows vidí GPU:

```powershell
nvidia-smi
```

Musí se objevit **RTX Spark N1X** a verze driveru. Pokud ne, nepokračujte
a zkontrolujte, že máte ARM64 driver, ne x64.

4. **Nastavte 96 GB dedikované GPU paměti.** Ve Windows jde o podíl
   z 128GB poolu; zbylých zhruba 32 GB zůstane systému.

5. **Zvětšete odkládací soubor.** CUDA alokace jdou ve Windows přes
   system commit, takže malý pagefile způsobí OOM i při volné paměti
   na GPU. Postup: *Advanced system settings → Performance → Settings →
   Advanced → Virtual memory → Change*, vypněte automatickou správu,
   vyberte NVMe disk a nastavte **Initial 98304 MB**, **Maximum
   131072 MB**. Potvrďte a restartujte.

## Krok 2: Nainstalujte vLLM pro Windows ARM64

1. Stáhněte **Windows ARM64 ZIP** z
   [releases projektu](https://github.com/devjeonghwan/vllm-for-rtx-spark/releases).
2. Rozbalte ho do krátké cesty, například `C:\vllm-spark`.
3. V PowerShellu v této složce spusťte instalaci:

```powershell
.\scripts\install.ps1 -Python python
```

Skript vytvoří `.venv` a nainstaluje přiložené kolo vLLM. PyTorch a
FlashAttention stahuje z NVIDIA. Instalace trvá několik minut.

## Krok 3: Stáhněte model od NVIDIA

Model je na Hugging Face jako `nvidia/Qwen3.8-Flash-Next-FP4-Local`.
Potřebujete nástroj `hf` (součást `huggingface_hub`):

```powershell
python -m pip install -U huggingface_hub
hf download nvidia/Qwen3.8-Flash-Next-FP4-Local --local-dir C:\models\Qwen3.8-Flash-Next-FP4-Local
```

Je to desítky GB. Nastavte si předem `HF_HOME` na disk, kde je místo,
pokud ho chcete mít jinde než na systémovém.

## Krok 4: Spusťte server

```powershell
.\.venv\Scripts\vllm.exe serve C:\models\Qwen3.8-Flash-Next-FP4-Local `
  --config configs\qwen3.8-flash-next\gpu-96gb-draft-kv-bf16.yaml
```

Konfigurace počítá s **96 GB na GPU**, MTP spekulativním dekódováním,
CUDA grafy, kontextem **409 600 tokenů** a až **16 souběžnými požadavky**.

První start připravuje PLE cache a může trvat několik minut. Až server
napíše, že poslouchá na `http://127.0.0.1:8000`, je hotovo.

Podle dostupné paměti vyberte jiný profil:

| GPU | KV budget | Profil |
|---|---|---|
| 90 GB | 12 GB | `gpu-90gb-draft-kv-bf16.yaml` |
| 96 GB | 18 GB | `gpu-96gb-draft-kv-bf16.yaml` (výchozí) |
| 108 GB | 27 GB | `gpu-108gb-draft-kv-bf16.yaml` (experimentální) |

## Krok 5: Ověřte API

V druhém PowerShellu:

```powershell
curl.exe http://127.0.0.1:8000/v1/models
```

Odpověď musí obsahovat model `Qwen/Qwen3.8-Flash-Next`. Pak zkuste chat:

```powershell
'{"model":"Qwen/Qwen3.8-Flash-Next","messages":[{"role":"user","content":"Ahoj, odpověz jednou větou."}]}' `
  | curl.exe http://127.0.0.1:8000/v1/chat/completions -H 'Content-Type: application/json' --data-binary '@-'
```

## Krok 6: Připojení z dalšího zařízení

Server ve výchozím nastavení poslouchá na `127.0.0.1`. Pro sdílení
v kancelářské síti přidejte `--host 0.0.0.0`, otevřete port 8000 ve
firewallu a **nezapomeňte na autentizaci** — výchozí vLLM server ji
nemá. V klientovi použijte `http://adresa-stroje:8000/v1` a model
`Qwen/Qwen3.8-Flash-Next`.

## Krok 7: Co dál

- **Open WebUI** nebo **LM Studio** jako chat rozhraní přes OpenAI API.
- **OpenCode / OpenClaw** pro agentní práci s kódem.
- **Automatické spuštění** přes Task Scheduler.
- **Monitoring** — `nvidia-smi`, Task Manager, teploty a příkon.

## Když to nefunguje

| Příznak | Co zkontrolovat |
|---|---|
| `nvidia-smi` nic neukáže | ARM64 driver, Windows Update, restart |
| `install.ps1` spadne | ARM64 Python 3.13, ne x64; dlouhá cesta bez mezer |
| `vllm.exe` chybí | instalace nedoběhla; spusťte skript znovu |
| CUDA OOM i při volné GPU | malý pagefile — 98304/131072 MB |
| Model se dlouho načítá | normální; první start plní PLE cache |
| Port 8000 obsazený | přidejte `--port 8001` |
| Pomalé na notebooku | nabíječka, 96 GB GPU alokace, kontrola throttlingu |

Když tabulka nestačí, pokračujte v
[řešení problémů](/temata/provoz/reseni-problemu/) — společný postup
pro všechny platformy.
